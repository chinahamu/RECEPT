# SQLiteバックアップ・障害復旧

対象はRECEPTのSQLite全体です。患者情報、診療・会計の下書き、公式マスター、確定・訂正の各版、アクセス監査ログ、職員アカウントとパスワードハッシュを同じ時点の状態で保存します。開発環境では架空データで復元訓練を行います。

設計の参照元は、厚労省「医療情報システムの安全管理に関するガイドライン」第7.0版 [システム運用編 §11、§12.2、§18](https://www.mhlw.go.jp/content/10808000/001716295.pdf) です。複数世代の確保と隔離保管、復元手順と訓練を扱っています。

## 取得と確認

1. RECEPTを起動するOSユーザーで実行します。バックアップ元は `RECEPT_DB` で設定し、未設定時は `data/recept.sqlite3` を使用します。保存先にはアクセス制限した専用の領域を指定します。
2. `create` はSQLiteの [VACUUM INTO](https://www.sqlite.org/lang_vacuum.html) で、稼働中でもコミット済みの整合したスナップショットを作ります。世代ごとのディレクトリにDBを置き、検査後に `manifest.json` を確定します。既存世代の上書き・削除は行いません。
3. `verify` はファイルのサイズ・SHA-256、SQLiteの構造と外部キー、監査ログのハッシュ連鎖、確定記録と訂正履歴を検査します。監査ログ・確定記録がまだ存在しない旧スキーマでは、その検査結果を `null` と表示します。結果はJSON、失敗時は非ゼロ終了コードです。

```sh
npm run --silent db:backup -- create data/backups
npm run --silent db:backup -- verify "<create が出力した generation>"
```

`data/backups` は同一端末での動作確認用の例です。実際に隔離保管する際は、完了した世代のディレクトリ全体をアクセス制限・暗号化された保管先に複製し、コピー先で `verify` を実行します。日次で運用する場合は少なくとも3世代を目安とし、一部を端末・ネットワークから切り離すか書き込み不可にします。実行頻度、使用する複数の保管方式、保存期間、失敗時の通知先は施設の運用に定め、定期実行と保管はOS・ストレージ側で設定します。

マニフェストのハッシュは破損の検出に使います。DBとマニフェストを共に書き換えられる場合に備え、検証結果を別の保護された場所に記録してください。バックアップのDBは平文SQLiteです。Windowsでは保存先のACLも管理してください。画面のデモJSONスナップショットは診断用の出力です。

## 障害時の復元

1. 障害発生時刻、影響範囲、バックアップの候補時刻を記録します。攻撃や端末侵害が疑われる場合は対象を隔離し、安全を確認した別環境で復元します。感染の可能性がある世代を起動しないようにし、施設の連絡体制と代替業務手順を使います。
2. 選んだ世代を `verify` で検査し、別の専用フォルダーに新しいDBとして復元します。復元先フォルダーは事前に作成します。元DBと既存ファイルは上書きされません。復元先にはアトミックなファイル公開に使うハードリンク対応のローカルファイルシステムを使用します。
3. 隔離した開発環境で `RECEPT_DB` を復元先に設定して起動します。患者台帳、公式マスター、請求確定記録の最新・旧版が期待どおり表示されることを確認します。`npm run --silent audit -- verify` で監査ログの連鎖も検証します。
4. バックアップ取得時点から障害発生までの未反映分を確認し、別記録と突き合わせます。復旧の判断後、サーバーを止めて参照先を切り替えます。復元先では職員の有効状態とパスワードが取得時点に戻るため、取得後に無効化・再発行したアカウントを照合し、再適用します。元DBと関連ファイルは、調査や切り戻しができるよう保管します。訓練では復元所要時間、復元した世代、欠落期間、画面・監査の確認結果を残します。

```sh
npm run --silent db:backup -- restore "<確認済みの世代フォルダー>" data/recept-restored.sqlite3
RECEPT_DB=data/recept-restored.sqlite3 npm run dev
# 起動と画面確認後、別ターミナルで実行
RECEPT_DB=data/recept-restored.sqlite3 npm run --silent audit -- verify
```

PowerShellでは環境変数を `$env:RECEPT_DB = 'data/recept-restored.sqlite3'` と設定してから各コマンドを実行します。処理が中断しマニフェストがない世代は検証・復元できません。復元が中断した場合は、再実行前に対象パスの既存ファイルを確認し、別名での復元から始めてください。
