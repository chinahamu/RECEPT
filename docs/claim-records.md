# 請求記録の確定・保存

厚労省「医療情報システムの安全管理に関するガイドライン」第7.0版 [システム運用編 §14.3](https://www.mhlw.go.jp/content/10808000/001716295.pdf) の真正性、見読性、保存性を、RECEPTの院内デモ構成に反映する機能です。

| 要件 | RECEPTでの対応 |
| --- | --- |
| 真正性 | 確定前にサーバーが算定した内容を表示し、その内容のハッシュとワークスペースの版が一致する場合に確定します。確定日時、最後の入力者、確定者、患者内部ID、診療月、版、訂正元、訂正理由を保持します。確定版は追記専用です。詳細表示・CSV生成前に記録のチェックサムを検証し、確定とアクセスログを同じトランザクションで保存します。 |
| 見読性 | 請求確定記録から患者氏名・カルテ番号で検索し、診療月、各版、確定日時、点数、明細、保険・公費、訂正理由を画面で確認できます。各版をUTF-8 JSONでも出力できます。 |
| 保存性 | 保存形式と算定ルールに版を付け、確定時のデータ・点数を保持します。患者台帳の変更、デモリセット、再起動から独立して確定版を保持し、自動消去しません。既存DBは初回APIアクセス時にスキーマ4に移行します。 |

## 操作

1. **会計・診療入力**で患者を選択し、**請求記録の確定内容を確認**を押します。対象は現在のデモ診療月です。傷病名、明細、保険・公費、算定点数・金額を確認し、確定します。
2. 訂正時は下書きを更新し、改めて確認画面を開いて訂正理由を入力します。確定により版が増え、以前の版を引き続き閲覧できます。確認後にデータが変更された場合は、もう一度内容を確認します。
3. **請求確定記録**から過去の版を検索・表示できます。**デモ請求CSV出力**は、対象月の各患者の確定済み最新版に基づきます。下書きの変更は、訂正版を確定した後に反映されます。

算定明細は対象月の診療分を使います。傷病名は対象月末までに開始した記録を保持します。確定時の明細別点数と集計結果、デモ点検結果、判明する公式マスターの取込ID・ファイル名・更新日・SHA-256を保存します。デモ初期データや移行前に登録された明細に、後からマスターの版を推定して付けることはありません。旧版の操作履歴から確定記録を復元することもありません。

## 導入時の運用

- この開発版の確定記録は架空データ用です。現行の利用者は匿名と表示されます。確定記録には認証済みの入力者・確定者を受け取る仕組みがあります。本番には、個人認証、入力・確定・閲覧・出力の権限制御と、信頼できる時刻源への同期が必要です。
- [療養担当規則第9条](https://www.mhlw.go.jp/web/t_doc?dataId=84035000)により、療養の給付の担当に関する帳簿等は完結の日から3年、患者の診療録は完結の日から5年です。導入施設で法定保存対象と完結日を定義し、個別に必要な期間と廃棄手順を管理してください。RECEPT内のデモ確定日時から廃棄日を算出する処理はありません。
- SQLite全体を整合性のある手段でバックアップし、隔離した環境で復元後に旧版の検索・閲覧・出力を検証してください。画面のデモスナップショットには確定記録が含まれません。復元には業務DB全体のバックアップを使用します。記録のSHA-256は破損の検出に用います。DBを直接操作できる権限の制限、保護されたバックアップ、長期保存時の移行検証は運用側で実施します。
- 正式な電子レセプトの作成・送信、審査結果、返戻・再請求の管理は別途実装が必要です。デモCSVとJSONは審査支払機関へ提出できません。
