# 厚生労働省ガイドライン第7.0版への対応状況

- **確認日** 2026年11月11日
- **対象** RECEPTの `main`（実装確認コミット [`b9df191`](https://github.com/chinahamu/RECEPT/commit/b9df191efc6fd80b012aba528a8c7c2d274b2a6c)）。架空データを使う、同一PC上の開発・プレビュー環境
- **基準資料** 厚生労働省「医療情報システムの安全管理に関するガイドライン 第7.0版」、[令和8年9月Q&A][qa]、令和8年6月のサイバーセキュリティ対策チェックリストとBCP資料。[厚労省の公式資料一覧][mhlw]

**現状は実務利用前の開発段階です。** 下表は主要項目の実装確認であり、実環境の適合判定には、医療機関の運用、導入構成、委託関係とその証跡の確認が必要です。現行版は架空データでの検証に使用してください。

## 対応状況

「実装済み」は記載した範囲で動作するもの、「一部実装」は追加の実装・構成が必要なもの、「未実装」は該当機能が現行版にないものです。「運用で対応」は導入先での手順・体制・設定が必要な項目、「範囲外」は現行構成で使わない機能で、導入範囲が変わる際に適用を見直します。章番号は特記のない限り[システム運用編][operation]です。

| ガイドラインの観点 | 状況 | RECEPTで確認した内容 | 導入・実務利用に向けた残件 |
| --- | --- | --- | --- |
| 利用者識別・認証（§14.1.1） | 開発版で実装済み | 個別の職員IDとソルト付きscrypt、ログイン失敗の試行制限、30分のセッション。ログアウト、アカウント無効化・パスワード再発行で失効する。[利用者認証と職種別権限](../README.md#利用者認証と職種別権限) | 採用・異動・退職に伴う申請・棚卸し、本人確認を伴う再発行、端末の離席時ロックを運用に組み込む。 |
| 二要素認証（§14.1.1） | 未実装 | 開発中は頻繁なログイン・ログアウトによる作業負担を避けるため、二要素認証を実装しない方針。[README](../README.md#利用者認証と職種別権限) | 令和9年4月1日時点で稼働を想定するシステムの新規導入・更改に関する要件と経過措置を確認し、アプリのログインとサーバーOSの二要素認証または同等措置を導入構成ごとに判断する。 |
| 職種・業務別の認可（§14.2） | 一部実装 | 受付・看護師・医師・管理者の階層をAPIで検査。診療・算定の編集と請求確定は医師以上、マスター管理・データ出力等は管理者。現行は職種単位で、患者・担当部署単位の参照範囲制御は未実装。[API](../server/api.ts) | 導入先の業務分掌に合わせて閲覧範囲・権限分離を確認し、必要な粒度で制御を追加する。 |
| アクセスログ・監査（§17） | 一部実装 | APIの操作・結果、認証済み職員ID、ログイン時刻、対象IDを追記専用ログに保存。ハッシュ連鎖の検証、チェックポイント照合、ローカルレビューコマンドを提供。成功ログの記録に失敗した場合は患者情報の返却・業務更新を抑止する。[アクセスログと監査](access-audit.md) | 信頼できる時刻源、ログ閲覧権限、保存期間、外部チェックポイント、定期レビュー、異常検知と通知先を設定する。 |
| 記録の確定と電子保存（§14.3の真正性の考え方、企画管理編） | 一部実装 | デモ請求の確定内容、職員ID、日時、点数・明細、判明したマスター版を固定。訂正理由付きで新しい版を追記し、旧版を検索・表示できる。[請求記録の確定・保存](claim-records.md) | 対象文書ごとに法定保存の適用・完結日を定義し、長期の見読性・保存性、移行、廃棄を検証する。療養担当規則第9条の保存期間は対象の帳簿等が完結日から3年、患者の診療録が5年。[療養担当規則][retention] |

## 算定・電子請求の進捗

以下は医療情報の安全管理とは別に、実際の保険請求に必要な機能の状況です。

| 項目 | 状況 |
| --- | --- |
| 医科基本マスター | 公式の7種類を利用者が手動取込できる。診療入力で使う範囲は傷病名と一部の固定点数の外来診療行為。正式算定の適用日・算定条件、医薬品・特定器材等の対応は途上。[公式マスターの対応範囲](official-masters.md) |
| 正式算定、電子レセプト、返戻・再請求 | 現行はデモ算定・点検・CSVと訂正版の管理まで。医科の標準仕様・記録条件仕様に沿った提出用データ、送信結果の照合、返戻取込・再請求、本番接続試験が未対応。[電子レセプトの作成][claim-specs]・[オンライン請求の手続きと確認試験][online-claim] |
| オンライン資格確認 | 本番連携は未実装。導入先の接続方式、利用申請、資格情報の取込・更新を確認する。[厚労省の案内][eligibility] |

## 検証の範囲

架空データでの[テスト](../server/workspace.test.ts)では、未認証・権限外の操作の拒否、セッション失効、監査記録、請求記録の訂正・復元、出力制限、稼働中DBからのバックアップ・別DBへの復元を確認しています。確認コマンドは `npm test`、`npm run lint`、`npm run build` です。医療機関の実環境での受入、Windows ACL・復元、オンライン請求・資格確認の接続は未検証です。
