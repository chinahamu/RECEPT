# 開発時のデータ保護

架空データを使う開発環境向けの対策です。厚労省「医療情報システムの安全管理に関するガイドライン」第7.0版 [システム運用編](https://www.mhlw.go.jp/content/10808000/001716295.pdf) §7の持ち出し管理と、§12の情報機器・記録媒体の管理を設計の参照元としています。

| 項目 | 開発環境の対策 |
| --- | --- |
| 接続 | 開発サーバーとプレビューの待ち受けはループバックに限定します。APIでは接続元・Hostと、ブラウザが送る場合はOrigin・Fetch Metadataを確認します。 |
| ブラウザ | API応答は `Cache-Control: no-store` を指定します。他のオリジンによる応答の読み込みや画面のフレーム埋め込みを制限します。 |
| 保存 | POSIXでは新規のDBディレクトリを `0700`、DBを `0600` で作成します。既存DB・ジャーナル等に他ユーザーのアクセス権がある場合や、DBの親ディレクトリに他ユーザーの書き込み権限がある場合は起動後のDBアクセスを拒否します。DBや関連ファイルへのリンクも拒否します。SQLiteの一時ストアはメモリを使用し、削除時の上書き設定を有効にします。 |
| 出力 | 請求CSVのプレビュー・コピー・保存、スナップショットJSON、請求確定記録JSONのアプリ内出力は、画面とAPIの両方で既定無効です。有効時は画面で確認してからファイル保存・コピーし、APIへの出力要求と拒否を監査ログに記録します。 |

### デモ出力を使うとき

架空データで出力を検証する場合に限り、プロセス起動時の環境変数 `RECEPT_ENABLE_DEMO_EXPORTS=1` を設定します。

POSIXシェルの場合

```sh
RECEPT_ENABLE_DEMO_EXPORTS=1 npm run dev
```

Windows PowerShellの場合

```powershell
$env:RECEPT_ENABLE_DEMO_EXPORTS = '1'
npm run dev
# 停止後に環境変数を解除
Remove-Item Env:RECEPT_ENABLE_DEMO_EXPORTS
```

プレビューにも同じ設定を使えます。出力先は端末側で管理してください。出力は平文のCSV・JSONです。ダウンロードの完了や、OS・ブラウザの機能による閲覧済み情報のコピーはアプリから観測できません。

### DBの保管

POSIXで既存DBの権限エラーが出た場合は、サーバーを止め、DBファイルと同じディレクトリにある実在の `-journal`、`-wal`、`-shm` の所有者・権限を確認します。DBと関連ファイルを起動ユーザーのみに制限し、専用ディレクトリに置いてください。権限調整の例は、専用ディレクトリに対する `chmod 700 data` とDB本体に対する `chmod 600 data/recept.sqlite3` です。

Windowsではファイル・リンクの検査を行います。DBのフォルダーとファイルのアクセス制御にはWindowsのACLを設定してください。SQLite本体と出力ファイルの暗号化はOS・ストレージ側の構成に委ねています。SQLiteの削除時上書きは、バックアップ、ファイルシステムの履歴、記録媒体上の完全消去まで保証するものではありません。
