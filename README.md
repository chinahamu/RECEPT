# レセプト

RECEPTは、一般病院の外来・入院業務を対象とする、院内サーバーまたは院内PCで動作する医科レセコンの開発プロジェクトです。[DENCAL](https://github.com/chinahamu/DENCAL) と連携し、保険資格の管理、外来・入院の算定、会計、月次請求、返戻・再請求を段階的に実装します。

> [!IMPORTANT]
> **開発初期のため、現在は実務利用できません。** 動作確認には架空データを使ってください。実患者の情報を入力したり、実際の診療・会計・保険請求に使用したりしないでください。

## 初期セットアップ

Node.js 22.13以降と Python 3.10以降（JSON関数が使えるSQLite）を使います。

```sh
npm ci
npm run db:init
npm run staff -- create demo-admin admin
npm run dev
```

1. ターミナルに表示されたURLを同じPCのブラウザで開き、職員IDとアカウント作成時に表示されたパスワードでログインします。
2. **院内サーバー・マスタ → 公式マスターの取り込み・参照** を開きます。画面のリンクから、厚労省の医科向け基本マスター7種類の全件版をダウンロードします。
3. ZIPを解凍し、元のファイル名のCSV・TXTを1つずつ選びます。公式配布ページの更新日を確認し、「取り込む」を押します。
4. 画面上部の「公式マスター 7/7種取込済み」を確認します。[公式配布元・対象ファイル・詳しい操作手順](docs/official-masters.md)

2026年11月の架空の外来データで、以下の操作を確認できます。

- **会計・診療入力** — 取り込んだ公式マスターから傷病名と対応する固定点数の医科診療行為を追加し、摘要やデモ会計を保存できます。
- **レセプト自動点検** — サンプルルールで個別・一括点検を行い、補正候補の適用と明細プレビューができます。
- **患者台帳** — 架空患者と保険情報を登録し、会計・診療入力画面へ移動できます。
- **院内サーバー・マスタ** — 公式マスターの手動取り込み・検索、操作履歴の確認、JSONスナップショットの出力、デモデータのリセットができます。
- **請求確定記録** — 患者・診療月ごとに内容を確認して確定し、訂正理由付きの版を追加できます。過去の版は検索・閲覧・JSON出力できます。
- **デモ請求CSV出力** — 対象月の確定済み最新版をプレビュー、コピー、保存できます。[請求記録の確定・保存](docs/claim-records.md)

### 保存と算定

DENCALと同じく、React／TypeScriptの画面、Node.js／TypeScriptのサーバー、SQLite、PythonのDB初期化を使用します。算定・点検・CSV生成はサーバーで実行します。患者、傷病名、算定明細、操作履歴はSQLiteに保存します。画面の操作履歴とJSONスナップショットには直近50件を表示・出力します。

`db:init` は `data/recept.sqlite3` を作成し、既存ファイルの上書きを拒否します。サンプル患者は初回のAPIアクセス時に投入します。別のDBを使う場合は `npm run db:init -- data/another.sqlite3` で作成し、起動時に環境変数 `RECEPT_DB` に同じパスを指定します。

この開発版は同じPCからの利用を前提としています。CSV・JSONの出力は既定で無効です。[開発時のデータ保護](docs/development-data-protection.md)に出力の有効化とDBファイルの保管条件をまとめています。オフライン切替は資格情報の表示を確認するためのデモです。点検・算定・CSVは操作確認用です。正式な算定・請求仕様への対応は今後進めます。

```sh
npm run lint
npm test
npm run build
npm run preview
```

`dev` と `preview` ではAPIも起動します。

## アクセスログと監査

開発版のAPIアクセスは、画面の操作履歴とは別の追記専用ログに記録されます。ログの確認・整合性検証と、本番導入時に必要な対応は[アクセスログと監査](docs/access-audit.md)を参照してください。

## バックアップと復元

`npm run --silent db:backup -- create data/backups` でSQLite全体を世代ごとに保存します。検証・別ファイルへの復元、隔離保管と復元訓練は[バックアップ・障害復旧手順](docs/backup-recovery.md)を参照してください。

## 利用者認証と職種別権限

権限は **管理者 ＞ 医師 ＞ 看護師 ＞ 受付** の順に、下位職種の操作を継承します。

| 職種 | 操作 |
| --- | --- |
| 受付 (`reception`) | 患者・診療情報と点検結果の閲覧、患者・保険情報の登録 |
| 看護師 (`nurse`) | 受付の操作。現時点では看護師専用の操作はありません |
| 医師 (`physician`) | 傷病・算定明細の編集、個別・一括補正、請求確定・訂正と確定記録の閲覧 |
| 管理者 (`admin`) | 公式マスター取込・管理、操作履歴閲覧、デモリセット・オフライン切替。デモ出力設定が有効な場合はCSV・JSONの出力 |

OS上でDBを管理するユーザーが、`npm run staff -- create <職員ID> <職種コード>` で職員を追加します。個別に生成したパスワードは作成時にのみ端末に表示されます。`npm run staff -- disable <職員ID>` で無効化し、`npm run staff -- reset <職員ID>` でパスワードを再発行して再有効化できます。無効化・再発行で既存セッションは失効します。既存DBは作り直さず、`staff` コマンドの実行時に移行できます。

パスワードはソルト付きscryptで保存し、ログイン失敗には試行回数の上限を設けています。セッションはログインから30分、ログアウトまたはサーバー停止で失効します。同じ職員IDの再ログインは以前のセッションを終了します。

**開発中は二要素認証（2FA）を実装しません。** 動作確認でログイン・ログアウトを頻繁に繰り返すため、追加の認証手順で作業が煩雑になるのを避ける方針です。本番導入に向けた認証強化として別途対応します。

## 開発方針

機能を一つずつ実装し、架空データで実際に画面を操作しながら、現場の業務に合わせて調整します。初期は外来の基本業務から着手し、入院・病棟業務へ段階的に広げます。

厚生労働省の「医療情報システムの安全管理に関するガイドライン 第7.0版」を設計の基準とし、要件と機能の対応、実装状況、導入前の残件は[厚労省ガイドラインへの対応状況](docs/mhlw-guideline-status.md)にまとめています。現時点の位置付けは開発初期です。[厚生労働省のガイドライン](https://www.mhlw.go.jp/stf/shingi/0000516275_00006.html)

## DENCAL連携

DENCALからの受信・受領結果照会と、RECEPTの **DENCAL受信** 画面での患者突合を利用できます。送受信とも同一PCの試作構成です。DENCALの **実施記録・RECEPT連携** で表示される施設ID・送信元IDを確認し、RECEPTを起動する環境で次の値を設定します。

| 環境変数 | 値 |
| --- | --- |
| `RECEPT_DENCAL_FACILITY_ID` | DENCALに表示される施設ID（10桁） |
| `RECEPT_DENCAL_SENDER_ID` | DENCALに表示される送信元ID |
| `RECEPT_DENCAL_TOKEN` | 連携専用の共有トークン。DENCAL側の `DENCAL_RECEPT_TOKEN` と同じ値 |

RECEPTの起動後、DENCAL側の `DENCAL_RECEPT_URL` をRECEPTのループバックURLに向けます。設定する送信元は1件です。職員がRECEPTにログインし、**DENCAL受信 → 詳細** から、DENCALの患者IDとRECEPTのカルテ番号・氏名・生年月日を照合して紐付けます。台帳に患者がいなければ、既存の **患者台帳** で登録してから紐付けます。

送信の再試行で同一データが重複登録されることはありません。未紐付け・未登録コード・対象外の算定条件や単位・先行版待ちは確認待ちとして表示されます。受領結果を開くたびに、患者台帳と現時点の取込マスターで再判定します。デモリセット後は受信履歴を保持し、台帳を入れ直すため患者の紐付けを再確認します。請求下書きへの反映は後続工程です。

## 診療報酬の算定とオンライン資格確認

### 診療報酬の算定

健康・医療共通算定モジュールの本番利用は、対応レセコンを導入した医療機関を通じて行います。本プロジェクトでは、医療機関名義で契約・利用手続きを進められる連携先を確保できていないため、本番環境に接続できず、同モジュールは利用しません。[厚生労働省の案内](https://www.mhlw.go.jp/stf/seisakunitsuite/bunya/kenkou_iryou/iryouhoken/newpage_00016.html)

RECEPTに独自の算定機能を段階的に実装し、対応する診療行為の診療報酬点数と患者負担額を院内で計算できるようにします。

### オンライン資格確認

オンライン資格確認は、連携先の医療機関名義での利用申請と、接続方式に応じた設定が必要です。本プロジェクトでは利用手続きや本番接続に必要な環境を確保できていないため、本番連携は未実装です。[医療機関等向け総合ポータルサイトの案内](https://iryohokenjyoho.service-now.com/csm?id=kb_article_view&sysparm_article=KB0010416)

## 将来の利用料金とライセンス方針

- **医療機関による直接利用** — 病院・クリニックが自院の業務に直接使う場合、ソフトウェア利用料は無料とする方針です。
- **業者による流用・販売** — 業者が本製品のコードを組み込んだ派生製品を非公開で販売・提供するなど、別途の商用許諾を受けて製品化する場合は、対象製品の売上に応じたレベニューシェアを基本とするライセンス料を徴収する方針です。料率、対象売上、報告方法は個別契約で定めます。

公開版は AGPL-3.0-only を採用する方針です。公開版のライセンス条件に従う利用・再配布には、別途の商用ライセンス料を課しません。本節は将来方針を示すもので、正式なライセンスの付与や契約条件の確定は、それぞれのライセンス文書と契約で行います。
